# Модель безпеки OTA-оновлень (Security Update Flow)

Цей документ описує повний ланцюг безпеки бездротових оновлень (Over-The-Air) у додатку MusicFlow Mobile, від моменту компіляції до встановлення на пристрій користувача.

## Загальний огляд (Overview)

MusicFlow використовує власну систему доставки оновлень (через GitHub Releases або Local Server) в обхід Google Play. Для забезпечення цілісності та безпеки користувача, система використовує:
1. Криптографічне хешування файлів (SHA-256).
2. Валідацію версій (Anti-Downgrade).
3. Цифрові підписи APK (Android Keystore).

## Повний цикл оновлення (Step-by-Step)

### Крок 1. Компіляція (Developer Build)
Розробник запускає `flutter build apk --release`. APK підписується єдиним приватним ключем (`release.keystore`), налаштованим у `build.gradle.kts`. Це гарантує, що Android дозволить встановлення оновлення поверх існуючої програми.

### Крок 2. Генерація контрольної суми (SHA-256)
Скрипт `server/publish_release.py` (або CI/CD пайплайн) після збірки зчитує APK файл і вираховує його криптографічний хеш за алгоритмом SHA-256.

### Крок 3. Формування маніфесту
Хеш SHA-256, розмір файлу в байтах та номер збірки записуються у файл маніфесту `version.json`.

### Крок 4. Завантаження клієнтом (Client Download)
Додаток на телефоні періодично або за запитом завантажує `version.json` через HTTPS.
- Якщо `buildNumber` в маніфесті більший за поточний — додаток ініціює завантаження APK-файлу в тимчасову директорію кешу (`getExternalCacheDirectories`).

### Крок 5. Валідація на пристрої (Client Verification)
Перед тим як ініціювати встановлення (`Intent.ACTION_VIEW`), клієнт:
1. Перевіряє наявність дозволу на пам'ять.
2. Самостійно розраховує SHA-256 завантаженого APK.
3. Порівнює отриманий хеш із хешем з `version.json`.
   - Якщо хеші **не збігаються** — файл вважається пошкодженим або скомпрометованим, завантажений файл видаляється, а встановлення переривається.
   - Якщо хеші **збігаються** — викликається нативний установник Android.

### Крок 6. Нативна валідація ОС (OS Verification)
Система Android перевіряє цифровий підпис завантаженого APK. Якщо підпис не співпадає з підписом уже встановленого MusicFlow, Android заблокує оновлення з помилкою `INSTALL_FAILED_UPDATE_INCOMPATIBLE`.

## Модель загроз (Threat Model & Mitigations)

| Загроза | Ризик | Захист (Mitigation) |
|---|---|---|
| **Man-In-The-Middle (MITM)** | Перехоплення трафіку та підміна APK файлу на шкідливий. | 1. Завантаження відбувається виключно через **HTTPS**.<br>2. Клієнт звіряє **SHA-256** з маніфестом. Навіть якщо зловмисник підмінить файл, хеш не співпаде, і файл буде відхилено. |
| **Корупція файлу під час завантаження** | Обрив мережі, збереження битого "наполовину" APK, що спричинить краш парсера пакетів. | Клієнтська перевірка SHA-256 не пройде, оскільки розмір та вміст файлу будуть відрізнятися від оригінального. |
| **Downgrade Attack** | Примусове встановлення старої, вразливої версії додатка (наприклад, v1.0 замість v1.5). | Жорстка перевірка `info.buildNumber > currentBuildNumber` перед ініціалізацією `installApk`. |
| **Підміна сервера маніфестів** | Зловмисник підставляє свій `version.json` зі своїм хешем. | Навіть якщо `version.json` скомпрометовано і клієнт завантажить шкідливий APK, **Android OS заблокує встановлення**, оскільки у зловмисника немає оригінального `release.keystore` для підпису. |
